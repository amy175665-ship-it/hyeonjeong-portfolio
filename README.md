# 백현정 웹 퍼블리셔 포트폴리오

**ABSORB. BUILD. GROW.**를 컨셉으로 만든 백현정의 반응형 웹 퍼블리셔 포트폴리오입니다. 현재는 화면 구성과 연출을 먼저 완성하고 있으며, 프로필 사진은 등록했고, 실제 소개·교육·프로젝트는 추후 등록합니다.

> 프로젝트 3개는 구성과 설명을 위한 자리 표시(작성 예시)입니다. 실제 작업 실적을 의미하지 않습니다.

## 포트폴리오 컨셉

### ABSORB. BUILD. GROW.

> 새로운 환경에서 필요한 것을 빠르게 파악하고, 직접 구현하며, 끝까지 완성해 성장으로 이어가는 사람.

선인장은 저를 표현하는 중심 소재입니다. 주어진 환경에 유연하게 적응하면서도 쉽게 흔들리지 않고 꾸준히 자라는 선인장의 특성을, 새로운 업무와 기술을 배우고 끝까지 결과물로 만들어내는 태도와 연결했습니다.

- **ABSORB.** 새로운 환경과 요구사항을 파악하고 필요한 것을 배웁니다.
- **BUILD.** 배운 내용을 직접 구현하며 제 것으로 만듭니다.
- **GROW.** 맡은 작업을 끝까지 완성하고, 그 경험을 다음 성장으로 이어갑니다.

| 소재 | 의미 | 포트폴리오에서 담을 이야기 |
| --- | --- | --- |
| 선인장 | 적응과 지속 | 환경이 달라져도 흔들리지 않고 끝까지 완성하는 태도 |
| 화분·흙 | 기반 | HTML·CSS·JavaScript를 비롯한 퍼블리싱 기본기 |
| 물 | 배움 | 새로운 기술과 요구사항을 배우고 적용하는 과정 |
| 햇살 | 경험과 기회 | 배운 것을 실제 작업에 적용하며 확장하는 경험 |

### 표현 방향

- 세 단어(ABSORB. → BUILD. → GROW.)를 페이지 전체의 순서로 씁니다. 첫 화면의 단어가 컨셉 장면과 각 섹션의 표시로 이어집니다.
- 성장의 이야기는 실제 배움과 작업 과정으로 보여줍니다. 컨셉을 설명하기 위해 경력·성과를 만들어내지 않습니다.
- 소재는 이야기를 돕는 장치입니다. 소개·기술·프로젝트 같은 메뉴와 콘텐츠 이름은 방문자가 바로 이해할 수 있게 유지합니다.

## 화면 구성

메인 페이지는 스크롤에 따라 아래 순서로 이어집니다.

| 순서 | 영역 | 내용 |
| --- | --- | --- |
| 1 | 첫 화면 | 햇살 배경, 마우스를 따라보는 3D 얼굴, 모래 언덕. PC에서는 ABSORB. BUILD. GROW. 세리프 단어가 비대칭으로 떠다니고, 글자에 마우스를 올리면 초록색으로 바뀌며 기울어집니다. ABSORB.의 S 위에서 모래가 바람에 휘며 흘러내립니다. |
| 2 | 모래 전환 | 스크롤하면 첫 화면의 글자와 모래 언덕이 모래알로 부서져 바람에 날리고, 3D 얼굴은 흐려집니다. 모래알은 다시 내려앉아 사막 언덕이 되고, 마지막 한 줌이 모인 자리에서 선인장이 돋아납니다. 위로 스크롤하면 거꾸로 재생됩니다. |
| 3 | 컨셉 장면 | 새싹이 선인장으로 자라며 모래바람을 버티고("직접 만들고"), 하늘이 노을·밤·새벽으로 바뀌는 동안 계속 자란 뒤("표면을 설계하고, 경험을 짓다."), 꽃이 피고 모래가 내려앉아 GROW.가 됩니다("웬만해선 시들지 않습니다."). 선인장이 돋아난 뒤부터는 스크롤하지 않아도 약 7초 동안 저절로 재생되며, 재생하는 동안에는 화면이 고정됩니다. |
| 4 | 소개·기술 (ABSORB.) | 이야기가 끝나고 휠을 한 번 내리면 선인장·GROW.·문구가 모래알로 부서져 바람에 흩어지고, 사막이 흰색으로 바뀐 뒤 모래알이 다시 모여 브라우저 창의 소개 페이지가 됩니다(약 2.2초, 도중에 스크롤하면 바로 끝남, 위로 스크롤하면 거꾸로). 이후 창 안에서 이어집니다. 창 안은 섹션마다 한 화면 높이이고 스크롤은 자유롭게 움직이며, 메뉴로 이동하면 섹션 하나가 화면에 딱 맞게 보입니다. 소개는 왼쪽 사진·이름·연락처, 오른쪽 소개 문장과 교육 목록(연도 / 항목 / 보조정보), 아래쪽에 끝없이 흐르는 기술 아이콘 띠. 소개는 ABSORB 표지로 시작합니다(선인장 모래알이 모래알 초상화와 큰 ABSORB.로 모이고, 왼쪽 위에 소개 문장이 크게 차오른 뒤, 모래알이 사진 칸으로 모여 실제 사진이 되며 문장이 제자리로 줄어들고 소개 페이지가 완성됨). 다음 페이지는 취미 타일 그리드(전시·카페·음악·여행·봉사 / 보드게임 / 러닝)로, 항목에 호버하거나 키보드·터치로 선택하면 왼쪽 큰 박스에 그룹 단어(ABSORB. / BUILD. / GROW.)와 뜻이 표시됩니다. 사진 슬라이드는 박스 안에서 재생되며 전체 화면으로 확대되지 않습니다. 그다음 브이로그 영상 자리 |
| 5 | 대표 프로젝트 (BUILD.) | 창 위쪽 탭(ABOUT·PROJECTS·DESIGN·CONTACT)으로 넘어갑니다. 흰 무대의 제목 위로 첫 프로젝트가 가운데서 번지듯 열리고, 예시 프로젝트 3개가 화면 전체 패널로 배경색이 바뀌며 이어지고(끝에서 밤색으로 어두워져 사이드 목록으로), 큰 제목·기능 띠·PC와 모바일 화면이 스크롤에 맞춰 나타나고 상세 페이지로 연결 |
| 6 | 디자인 (GROW.) | GROW 원의 끝에서 모래 고리가 화면에 머물고, 그 고리 위에 작업물 7개가 행성처럼 돕니다. 호버·포커스·탭하면 가운데에 나타나고 클릭하면 크게 봅니다(현재 "작성 예시" 자리 표시) |
| 7 | 연락처 (BLOOM.) | 창의 마지막 장면. 가운데서 밤이 퍼지고 3D 선인장에 꽃이 피며 3D 얼굴이 돌아오고, BLOOM.·큰 이메일 링크·저작권 표기가 나타납니다. 끝에서 창 막대가 내려오고 모래가 올라와 화면을 덮습니다 |

- 헤더는 가운데 선인장 로고(호버 시 종처럼 흔들림)와 햄버거 메뉴로 구성됩니다. 헤더 메뉴(ABOUT·PROJECTS·DESIGN·CONTACT)는 모두 브라우저 창 안의 해당 위치로 이동합니다.
- 마우스 사용 PC에서는 물방울 모양 커스텀 커서를 씁니다(링크 위에서 투명한 구로 바뀌고, 클릭하면 작은 물방울이 퍼짐).
- 모바일에서는 영문 세 단어를 숨기고 얼굴 중심으로 보여주며, 장면 배치를 단순화합니다.
- 모션 감소 설정에서는 연속 움직임을 멈추고 각 장면의 완성된 모습을 보여줍니다.

- PC 창 안의 캡슐 메뉴는 아래로 스크롤하면 숨고 위로 스크롤하면 다시 나타납니다. 소개 첫 진입·메뉴 이동 직후·키보드로 메뉴를 사용하는 동안에는 표시됩니다.

### 현재 상태와 숨김 처리

- 리디자인("A Living Digital Desert", 방향 B)을 단계별로 진행 중입니다. 승인된 동작 시안은 `artifacts/mockup-living-desert-20261008/index.html`을 브라우저로 열어 볼 수 있습니다.
- 1단계(완료): 모래 전환으로 드러난 창이 스크롤하면 전면 화면으로 풀리고(창틀 값 `--frame` 1→0), 창 안은 일반 스크롤로 소개 → 취미 → 프로젝트 → 디자인 → 연락처가 이어집니다. 전면이 되면 헤더가 화면 위에 떠서 지금 단계 단어(ABSORB. 등)를 보이고, 아래로 스크롤하면 숨었다가 위로 스크롤하면 돌아옵니다.
- 이전 구성(스크롤로 날아오는 브라우저 데모, 프로젝트 캐러셀 등)과 음성 소개 코드는 지웠습니다. 필요하면 git 기록에서 찾습니다.
- 브이로그는 영상이 생길 때까지 숨깁니다. 디자인 작업은 7개 자리 표시("작성 예시")로 궤도에 올라가 있습니다.

## 로컬 실행

저장소 루트에서 실행합니다. 아래 명령은 Windows PowerShell 기준입니다. 다른 셸에서는 `npm.cmd` 대신 `npm`을 사용합니다.

```powershell
npm.cmd ci
npm.cmd run dev
```

개발 화면: [localhost:3000](http://localhost:3000)

프로덕션 빌드와 실행:

```powershell
npm.cmd run build
npm.cmd run start
```

다른 포트를 사용하려면 다음처럼 실행합니다.

```powershell
npm.cmd run dev -- --port 3001
```

- 개발 서버와 프로덕션 빌드는 같은 `.next/` 경로를 사용합니다. 빌드 전에는 개발 서버를 종료하고, 빌드가 끝난 뒤 다시 실행하세요. 동시에 실행하면 산출물이 충돌해 스타일이나 모듈을 불러오지 못할 수 있습니다.
- 한글 제목 글꼴(Noto Serif KR)은 빌드할 때 Google Fonts에서 내려받으므로 인터넷 연결이 필요합니다.

## 폴더 구조

```text
app/
├─ layout.tsx                 공통 레이아웃, 글꼴, 커스텀 커서
├─ page.tsx                   메인 페이지(오프닝 → 브라우저 창 안의 섹션들)
├─ reset.css                  브라우저 기본 스타일 초기화(globals.css보다 먼저 불러옴)
├─ globals.css                전역 스타일
└─ work/[slug]/page.tsx       대표 프로젝트 상세 페이지
components/
├─ layout/                    SiteNav(헤더·전체 메뉴), SiteFooter(상세 페이지 푸터), MenuSand, SmoothScroll, scrollLock
├─ motion/                    SplitText·RollingWord(글자 단위 모션), useScrollDirection, scrollFrame(스크롤 연동 읽기→쓰기 묶음), useSeam(파트 경계의 들어옴·나감 값), styleWriter(바뀐 스타일 값만 쓰기)
├─ stage/                     windowState(지금 단계·창이 풀렸는지)
├─ sections/
│  ├─ AboutStory, AboutCover, HobbyFlow, WorkStory, GrowStory, DesignStory, ContactStory   브라우저 창 안의 소개·취미, 대표 프로젝트, 디자인, 연락처
│  ├─ hero/                   Hero, GrowthScene(PC 타이포), HeroAvatar·AvatarCanvas(3D 얼굴), SandStream(모래 줄기)
│  └─ concept/                ConceptScenes(컨셉 장면), scenes.ts, CoverSand(첫 모래 전환), CactusScene, WindGust, PollenGrow, SandHandoff(모래알 전환), WindowFrame(브라우저 창)
└─ ui/                        Reveal, ProjectLinks, ProjectTags, CustomCursor
data/                         소개·취미(profile), 기술(skills), 연락처(contact), 프로젝트, 디자인, 메뉴, 이야기 단계(stages), GROW 원의 세 단어(workStyle)
assets/                       원본 디자인 소스(커서·모래 PNG, 기기 목업). 배포되지 않음
public/                       화면에 쓰는 정적 파일(이미지 WebP, 로고, 3D 모델, 글꼴, 기기 목업)
artifacts/                    시안과 승인된 시안(사진·영상은 git 제외)
```

- 여러 섹션에서 쓰는 요소는 `ui/`, 첫 화면 전용 요소는 `sections/hero/`, 사막 이후 컨셉 장면은 `sections/concept/`에서 관리합니다.
- 원본 이미지는 `assets/`, 화면용 변환본은 `public/`에 둡니다. 원본을 바꾸면 WebP 변환본도 다시 만들어야 합니다.
- `.next/`와 `node_modules/`는 생성물이며 Git 관리 대상에서 제외되어 있습니다.

상세 페이지 푸터의 스타일은 `components/layout/SiteFooter.module.css`, 프로젝트 링크의 스타일은 `components/ui/ProjectLinks.module.css`, 프로젝트 태그의 스타일은 `components/ui/ProjectTags.module.css`에서 관리합니다. 프로젝트 상세 페이지의 스타일은 `app/work/[slug]/page.module.css`에서 관리합니다. 메뉴 모래 캔버스의 고정 스타일은 `components/layout/MenuSand.module.css`에서 관리합니다. 기본 본문 폰트·굵기와 `.sr-only`는 `app/globals.css`에서 직접 정의합니다. `.sr-only` 이름은 모래 전환과 소개 표지의 참조를 위해 유지합니다. Tailwind는 모든 컴포넌트를 CSS Modules로 전환한 뒤 설정(`tailwind.config.ts`, `postcss.config.mjs`)과 의존성(`tailwindcss`, `autoprefixer`, `postcss`)까지 제거했습니다. 브라우저 접두어는 Next.js 기본 PostCSS 설정이 붙입니다.

### 선택적 정보

- 소개 사진은 `profile.photo`, 소개글은 `profile.introduction`에 입력합니다. 현재 사진은 `/images/profile/profile-front.webp`이며, 값이 없으면 사진 자리 표시가 나오고 소개글은 숨깁니다. 빈 자격증 목록도 표시하지 않습니다.
- 기술별 설명은 `skills` 항목의 `description`에 추가할 수 있습니다. 값이 없으면 기술명만 표시합니다.
- 모래 이미지를 바꾸면 화면용 WebP를 다시 만들고, 모래 능선 높이와 전환 색이 맞는지 확인해야 합니다.

### 프로젝트 데이터

- `featured`: 대표 작업과 보조 작업을 구분합니다. 보조 작업이 있으면 대표 프로젝트 아래에 "이전 작업" 목록으로 표시됩니다.
- `placeholder`: 예시 여부를 나타냅니다. 실제 내용으로 바꾼 뒤 `false`로 바꾸고, 제목의 `PLACEHOLDER` 문구도 정리합니다. 예시가 하나도 없으면 안내 문구와 "작성 예시" 표시가 사라집니다.
- `scope`: 직접 담당한 범위와 참고 출처를 기록합니다.
- `categoryTags`, `featureTags`, `stack`: 분류, 구현 기능, 사용 기술을 표시합니다.
- `challenges`: 실제로 겪은 문제와 해결 방법을 `problem` / `solution`으로 기록합니다.
- `links.website`, `links.github`, `links.figma`: 실제 주소가 있는 링크만 표시합니다.
- `image`, `desktopImage`, `mobileImage`: 프로젝트 이미지는 `public/images/`에 두고 경로를 지정합니다. `desktopDevice: "monitor"`를 지정하면 `public/images/devices/desktop-monitor.png`, `mobileDevice: "gold-phone"`을 지정하면 `public/images/devices/gold-smartphone.png` 목업에 화면을 맞춥니다. JAJAK에 두 목업을 연결했습니다. 작은 화면에서는 이미지 묶음 아래로 설명이 이어집니다.
- `size`: 이전 카드 목록에서 쓰던 필드로, 현재 화면 배치에는 영향이 없습니다.

`/work/[slug]` 상세 페이지는 대표 프로젝트 데이터를 기준으로 구성됩니다.

## 화면 확인

코드 변경 후 `npm.cmd run build`로 빌드와 타입 검사를 확인합니다. `lint` 스크립트는 등록되어 있지만 별도 ESLint 설정은 준비되어 있지 않습니다.

화면 변경 시 다음 항목을 확인합니다.

- PC 1440×900, 태블릿 1024×768, 모바일 390×844·320px의 배치
- 첫 화면부터 프로젝트까지 스크롤했을 때 장면 전환, 역방향 스크롤
- 가로 넘침, 글자·버튼 겹침, 이미지 로딩 실패, 브라우저 오류
- 모바일 메뉴 열기·닫기, Escape 키, 키보드 포커스, 메뉴 링크 이동
- 첫 화면 글자 호버, 커스텀 커서, 프로젝트 상세 페이지 이동
- 모션 감소 설정에서의 동작

`artifacts/`에는 시안과 승인된 시안만 작업별 폴더로 남기고, 확인용 캡처는 확인이 끝나면 지웁니다. 시안 폴더 안의 스크립트는 로컬 Playwright 설치 경로에 의존하므로, 다른 환경에서는 경로를 조정해야 합니다. 정식 공통 테스트 환경은 아닙니다.
